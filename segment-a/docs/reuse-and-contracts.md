## Data routes and authority

- A1 produces a certified Cartridge through the frozen compiler. It is never
  connected to a permanent runner. A2 optionally invokes the original batch
  ingress adapter, recording exact output JSON in session dispatch history.
- A3 accepts existing returned envelope/ObservationArtifact structures. Their
  observation_id and canonical Observation_ID must agree; section_8_source's
  SHA-256 must match its exact decoded source_text. Batch/runner context is copied
  if supplied. Search invocation association is explicitly Operator-selected.
- Plain/Markdown UID headings are delineation affordances, not a new runner
  contract. Metadata absent from text remains absent. Exact input payloads are
  retained independently from cleaned display text.
- Existing returned fact_table requirement/preference qualifiers route verbatim
  into B's hard/soft requirements arrays. No decomposition, suitability score,
  SDNA operation or target-label rewriting runs in A. No returned keyword lexicon
  was established in this source; B permits its empty array.
- A4 emits one pair per selected UID because frozen B has one target_id and one
  raw_posting per invocation. It preserves operational provenance in existing
  history/audit_trail extension fields, retains the full corpus/payloads in the
  committed session snapshot, and emits only the selected target as raw_posting.
- B's Z_state fields are Operator references, not inferred. Optional SDNA manifest
  hash is absent because A has no candidate SDNA authority in R2. B verifies its
  independent candidate input using its unchanged gate. This does not resolve
  legacy A/B manifest canonicalization differences.

## Handoff boundary

Outputs use B's existing SEALED_A_ENVELOPE.json and STAGE_A_SIDECAR.json shapes;
Operator supplies candidate.sdna.yaml directly to B. Source status strings are
the existing B fixture's A_COMPLETE / complete:HANDOFF_TO_B. They designate a
prepared A artifact, not a successful B receipt; UI transaction state stays
COMMITTED, LOCALLY_VERIFIED or BLOCKED until real acceptance.

Local checks reuse B hydration and validate required strings/taxonomy arrays,
run/UID correspondence, source provenance and exact serialized version hashes.
Tests feed actual A4-generated bytes through frozen B acceptThreeFiles and
executeIngress, with SDNA present only in the test receiver. A separate test uses
the unchanged existing runner artifact builder before A3→A4→B ingress.

No transmission implementation is activated. The provisional Receiver interface
is a test seam, not a new public endpoint or permanent receipt schema. An exact
receipt must account for every selected UID and both sent hashes, with no missing,
duplicate or rejected entry. The test seam has a bounded one-second acknowledgment
wait; live receiver timeout/authentication policy remains unresolved.

## Failure and destructive-transition policy

REJECT is explicitly confirmed and cannot be undone or bypassed via UID/source
duplicates. Excluded evidence stays in the corpus. Commit requires a current
warning token and affirmative confirmation; selection edits invalidate that
warning. A4 failure does not replace/clear staging. A5 failure retains committed
versions. Reset requires a warning about all evidence/output loss and manual
saving; cancellation leaves workspace state unchanged. Browser navigation uses
the browser's beforeunload protection; custom wording is browser-dependent.
